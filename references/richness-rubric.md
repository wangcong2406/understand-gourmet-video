# 丰富性验收量表

> 目的：检查视频中值得保留的判断过程是否被充分召回。它与事实/格式闸门相互独立。
>
> **优先级：丰富性高于安全性。** 丰富但存在归属或置信度问题的内容应保留并标注；不能为了零 BLOCK 删除信息。丰富性不足时应回到原视频补理解，而不是用格式修补掩盖。

## 一、验收原则

1. 最低基线是 2026-08-19 生成的 `0011–0030` 丰富产物；新版本不得更薄。
2. 不设“每期必须 N 条规律”这类诱导编造的 KPI；检查的是**有机会却遗漏**。
3. 同时保留三种形态：完整原话、细粒度本期过程、可统计标签。后者不能替代前两者。
4. 电影学概念只用于还原判断如何在时间、身体、声音、镜头和互动中发生，不评价摄影审美。
5. 不确定性不是删除理由。保存可观察事实、竞争解释、支持/限制与当前未决状态。

## 二、单期覆盖检查

### A. 视听还原

- [ ] 全部重要口播保留逐字原话和时间戳
- [ ] 每个重要评价对象至少保留相关判断性动作，而非只写“中景/特写/正常咀嚼”
- [ ] 声音记录覆盖即时品尝、事后总结、后期旁白、互动/引述的区别
- [ ] 强判断附近的停顿、重复、语速、音高、笑/叹气、咀嚼中断等得到记录
- [ ] 口播—对象、刺激—反应、比较、反差、重复、回扣、省略等镜头关系得到扫描
- [ ] 每段有 `visual_status`、`visual_basis` 与花字可读性，能区分连续视频/抽样帧/纯音频/不可读
- [ ] JSON 中每个 reviewed 段都在 Markdown A1 留下同源 basis 的客观观察；无判断相关视觉信号时使用规范留痕，不编造内容
- [ ] 动作与反应序列由连续视频或连续帧支持，单帧只证明静态事实
- [ ] 花字、BGM、回放、开场/结尾位置等后期强调与专家言行分开归属，并标 `evidence_level`

### B. 本期判断过程

- [ ] 每个重要结论能回溯到一个完整 `judgment_episode`
- [ ] 事件包含初始预期、刺激、信息获取、反应、复核、推理、修正、结论和行动；无此环节时明确写无
- [ ] 重要比较和参照系完整：预期/实际、菜间、店间、地域、个人历史、价格/品质等
- [ ] “但是/不过/其实/可能/个人口味/虽然…但…”等转折得到逐项检查
- [ ] 言语—行为、即时—总结的一致/背离得到记录，矛盾不被调和
- [ ] 所有重要结论有 `观察/感受→参照/假设→推导→结论→行动` 链
- [ ] 判断弧线能解释哪一刻改变了单菜或整店判断

### C. 视频独有信号

- [ ] `expert_attention`、`verbal_attention`、`editorial_attention` 分开记录
- [ ] 强反应按时间序列记录，不把孤立表情直接翻译成情绪
- [ ] 无反应先验证可观察机会，并区分四态
- [ ] 专家、同伴/店员、摄影选择、后期包装的意义主体分开
- [ ] 跳切或省略造成的不可见部分被诚实标注

### D. 蒸馏回流

- [ ] 方法论六环节逐项完成机会扫描，空数组有 scan_notes
- [ ] 表达 DNA 保存完整原话和表达功能，不只给风格形容词
- [ ] 原始感官措辞与标准标签双存
- [ ] 个人经历、地域、同行/师傅、旧店旧菜等参照材料得到保存
- [ ] 价值观/红线、候选规律与“本期已经发生的过程”没有混为一层
- [ ] 开放解释保存竞争解释、支持、反证/限制和下游边界

## 三、密度诊断指标

以下仅用于发现批次漂移，不作为机械凑数目标。比较时按视频分钟归一化，并与同类内容/金标自身相比。5.3-Flash 分支必须把视觉信号拆层，不能再用单一 `visual_lines_per_min` 代表视觉理解：

- 理解正文字符/视频分钟
- `raw_caption_lines_per_min`：OCR/花字原始行，仅计覆盖，不代表视觉语义
- `raw_detector_lines_per_min`：人物/餐具/食物/场景分类，只作工具留痕
- `semantic_visual_lines_per_min`：提供静态外观、对象状态或情境增量的客观观察
- `judgment_action_lines_per_min`：与信息获取或行动结果相关的动作
- `continuous_reaction_sequences_per_min`：有连续视频或密帧支持的反应序列
- `generic_visual_ratio`：泛化 detector 行占全部 `[画面]` 的比例
- 有效 `[画面]`、判断动作、反应序列/分钟
- 完整原话字符/分钟
- 判断事件/主要评价对象覆盖率
- 比较、转折、修正、推理链/分钟
- 六环节有证据项数与扫描完成率
- 表达 DNA 原话样本/分钟
- 原始感官措辞/菜品
- 声画关系与剪辑关系/分钟
- `visual_coverage_ratio` 与四类 `visual_status` 分布
- `visual_md_coverage_ratio`：JSON 声称 reviewed 的时间段中，有多少在 A1 留下同源客观观察或规范无信号留痕
- direct_video / frame_sequence / single_frame / audio_timeline / editorial_inference 数量
- 有连续视觉证据的反应序列比例、已核验花字比例、无依据视觉声明数
- 开放解释及竞争解释覆盖率
- `main_dish_food_morphology_coverage`：主要菜品中有可见形态证据的比例
- `judgment_event_action_coverage`：判断事件中有动作边界证据的比例
- `reaction_window_continuous_coverage`：反应窗口有8fps/连续视频支持的比例
- `face_visible_microreaction_coverage`：脸清晰的强判断机会中完成FACS-lite编码的比例
- `shot_language_coverage` / `sound_event_coverage` / `editing_relation_coverage`
- `video_unique_fact_ratio`：删除ASR后仍成立的视频独有事实比例
- `claim_evidence_precision`：抽检高层claim可由ledger证据支持的比例
- `audio_restatement_ratio` / `duplicate_episode_weight_ratio`

Flash.2 批次验收读取 `references/visual-golden-v2.json`。OCR、对象检测、术语数量和全文长度均不得用于宣称超过基线；分母只统计真实存在且可观察的机会。

出现以下情况应判为“丰富性回归”，即使安全闸门零 BLOCK：

- 只剩菜品 sentiment/reason，没有本期判断过程
- 画面主要是景别、菜品外观和“表情自然”，缺判断动作
- B3/B4 大量空白且无机会扫描说明
- 原始感官措辞被标准标签替代
- 镜头时长直接解释成专家偏好
- 无反应未检查可观察机会
- 推断因为不能确认而被整体删除
- JSON 很长，但方法论、表达、比较、修正等高价值信号为空
- A1 没有 visual_status，无法区分未看画面与看过但无信号
- JSON 声称 `reviewed_frames` / `reviewed_video`，但 A1 视觉行是零或大部分 reviewed 段没有对应观察
- 用单帧证明停顿、复尝、眼神转移或镜头关系
- audio_only 段仍生成镜头、花字、BGM或剪辑结论
- Markdown 有 B5-B7，而 JSON 静默缺少对应字段
- A9-A15 重复粘贴原话却没有 episode_refs，导致同一证据被重复加权

## 四、视觉真实性抽检

机械校验只能证明视觉声明、帧资产、时间窗与 Markdown/JSON 留痕一致，不能证明模型真的读取过图片，也不能判断描述是否符合画面语义。因此每轮必须保留独立抽检：

- 校准批每份抽 2–3 条，覆盖静态观察、动作/反应序列、花字或不可读状态；原帧与对应 `[画面]` 行交给独立评审，任一硬事实不符即停止放量。
- 每个 10–20 期放量批随机抽至少 2 期、每期 2–3 条。
- 表情变化、停顿、复尝、看向同伴、退菜、蒙太奇和花字价格属于高风险声明，强制核验，不计入随机配额。
- 模型自报的已读帧清单只用于审计；若执行环境能产出不可由模型改写的工具访问日志，以工具日志为准。没有工具日志时，不得把自报清单称为实际读取证明。

## 五、建议金标集

从 `唐仁杰视频/understanding` 选择下列代表类型，建立人工“不可丢清单”。这些旧金标没有新字段，因此审计出现 `RICH_SECTION_MISSING` / `RICH_JSON_MISSING` 是预期的迁移诊断；金标的作用是校准内容召回与不可丢语义，不是要求旧文件通过新模板：

- `0011`：甜度阈值、颗粒感、个人口味演变、保存建议、打包外观不干扰判断
- `0014`：高画面密度、多对象与细节观察
- `0017`：多菜正餐、地域参照、传统/新潮、逐菜分化判断
- `0019`：高端菜、技术归因、个人口味与品质分离、品牌预期
- `0028`：多菜与复杂结构，用于检查覆盖完整性
- `0030`：短视频高段落密度，用于检查时间线和判断事件压缩

机器可读的批次基线与语义锚点在 `references/richness-golden.json`；`audit_richness.py --selftest` 会确认该文件存在且代表样本均有锚点。

每个金标文件人工维护：

1. 不可丢的原话；
2. 不可丢的判断动作和反应序列；
3. 不可丢的比较、转折和推理链；
4. 不可丢的六环节线索；
5. 不可丢的表达 DNA；
6. 不可丢的开放解释；
7. 旧产物中的过度推断（可保留但必须降级标注，不得直接复制成事实）。

## 六、丰富性与安全冲突时的处理

| 情况 | 处理 |
|------|------|
| 内容丰富、归属明确 | 正常保留 |
| 内容丰富、归属或解释不确定 | 保留在 `open_interpretations`，标竞争解释和限制 |
| 内容可能是后期强调 | 保留，agency 标 `editorial_attention`，不署名给专家 |
| 原话可疑但表达素材重要 | 原始 ASR 与最可能听辨并存，降低置信度 |
| rich 产物存在事实错误 | 修正或降级该条，不删除同一事件的其他可靠信息 |
| 内容安全但极薄 | 判丰富性回归，回原视频补理解 |

**总原则：安全问题采用“分层、降级、隔离”，不用“压缩、删减、默认留空”。**
